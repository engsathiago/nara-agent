# Local video frame OCR validation — 2026-11-26

The new source branch was run through the bundled Python environment with
`PYTHONPATH` pointing at the checkout. This is a local source validation; the
existing `04c395d0` DMG and ZIP do not include the new code.

A generated 640×360 image displayed `github.com/exemplo/repo`, then FFmpeg
encoded it as a two-second video. The first run used a sine audio track. The
real local macOS Vision adapter sampled four frames, identified the repository
text, archived one distinct text-bearing frame and returned `screen_text_local`.
The absent speech result remained visible as `local STT returned an empty
transcript`. The frame hash was
`4c5e4a94b12ac2aa123e58f68a3ab2f8f866eb151936b481dd0786b5b6d9424e`.

A second video used the same image and real Portuguese speech generated by
macOS `say`. The installed local faster-whisper backend and the real Vision
adapter returned `transcribed_local` with this combined extracted text:

> a Nara verifica resultados e preserva a fonte original.
> [screen @ 0.000s] github.com/exemplo/repo

The speech-only transcript has its own SHA-256
`27dfcbc5de7e7c73be84cedc4b7b063523fc85b921cd235bf2678be9f6c433c4`.
The visual evidence records the sampled time, frame hash, archived frame path,
OCR confidence and source hash. Tests separately cover audio-only and
screen-only partial outcomes, source-quoted claims, idempotence and claim
offset preservation when speech arrives after screen OCR.

These synthetic samples establish the local implementation path. They do not
measure accuracy on real Reels or guarantee detection of short text between
the maximum 60 sampled frames. Repository verification and skill promotion
remain separate gates.
